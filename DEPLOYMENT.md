# Deploying the Zoomers backend (free tier)

This guide gets the Zoomers API running on a public HTTPS URL at **no cost**,
using [Render](https://render.com) for the app and a free PostgreSQL database.
The repo already contains everything needed: a `Dockerfile`, a `render.yaml`
blueprint, automatic database migrations on first boot, and health checks.

When you're done you'll have a URL like `https://zoomers-api.onrender.com`, with
interactive API docs at `https://zoomers-api.onrender.com/swagger`.

---

## Option A — Render Blueprint (recommended, fewest steps)

Provisions the web service **and** the database together, wired automatically.

1. Push this repo to GitHub (already done) and sign in at
   <https://dashboard.render.com> with your GitHub account (free, no card).
2. Click **New → Blueprint**.
3. Select the `Zoomers_Time` repository. Render detects `render.yaml`.
4. Review the plan — a free web service `zoomers-api` and a free Postgres
   `zoomers-db` — and click **Apply**.
5. Wait for the first deploy (~5-8 min; it builds the Docker image, then the app
   runs database migrations on startup). When the service shows **Live**, open
   its URL and add `/swagger` to see the API.

That's it. The signing key is generated by Render, the database connection is
wired in automatically, and the schema is created on first boot.

### Free-tier limits to know
- **Cold starts:** the free web service sleeps after ~15 min idle. The next
  request wakes it and takes ~30-60s; after that it's fast. (The app shows a
  loading state during this.)
- **Database lifespan:** Render's *free* Postgres is deleted ~30 days after
  creation. For something longer-lived, use Option B's Neon database (free and
  persistent) — you can switch at any time by changing one environment variable.

## Option B — Neon database + Render web service (persistent data)

Use this if you want the database to last beyond 30 days.

1. Create a free database at <https://neon.tech> (no card). After the project is
   created, copy its **connection string** — it looks like:
   `postgresql://user:password@ep-xxxx.region.aws.neon.tech/dbname?sslmode=require`
2. Deploy the web service on Render as in Option A, **but** before the first
   deploy finishes (or under the service's **Environment** tab afterwards):
   - **delete** the auto-created `zoomers-db` database, and
   - set the `DATABASE_URL` variable to your Neon connection string.
3. Save — Render redeploys, the app parses the Neon URL, runs migrations against
   Neon, and comes up Live.

The app understands both URL-style (`postgres://…`) and key/value connection
strings, so no reformatting is needed.

## Environment variables (reference)

The blueprint sets these for you; this is what they mean if you ever set them by
hand (under the service's **Environment** tab):

| Variable | Value | Purpose |
|---|---|---|
| `DATABASE_URL` | `postgres://…` | Database connection (parsed automatically). |
| `Database__AutoMigrate` | `true` | Build/upgrade the schema on startup. |
| `Jwt__SigningKey` | *(generated)* | Secret that signs login tokens. Must be ≥ 32 chars. |
| `Jwt__Issuer` | `zoomers` | Token issuer. |
| `Jwt__Audience` | `zoomers.clients` | Token audience. |
| `ASPNETCORE_ENVIRONMENT` | `Production` | Runtime environment. |

Render injects `PORT` automatically; the app binds to it.

## After it's live

1. Note your service URL, e.g. `https://zoomers-api.onrender.com`.
2. Verify it:
   - `GET /health/live` → `200` (process is up)
   - `GET /health/ready` → `200` (database reachable)
   - open `/swagger` in a browser to try the API.
3. Point the Android app at it: set the app's `API_BASE_URL` to
   `https://<your-service>.onrender.com/api/v1/` and rebuild the APK. (The CI
   workflow produces the installable APK; see `android/README` for details.)

## Running the container locally (optional)

```bash
cd backend
docker build -t zoomers-api .
docker run -p 8080:8080 \
  -e DATABASE_URL="postgres://zoomers:devpassword@host.docker.internal:5432/zoomers?sslmode=disable" \
  -e Database__AutoMigrate=true \
  -e Jwt__SigningKey="a-local-signing-key-at-least-32-characters" \
  zoomers-api
# API: http://localhost:8080/swagger
```
